GPU: NVIDIA H200; CUDA: 13.0
Packages: {'torch': '2.13.0+cu130', 'triton': '3.7.1', 'apache-tvm-ffi': '0.1.11'}

Geometry experiment: BF16, hidden size 2048; same elementwise CUDA arithmetic, vector width 8.
Only rows per block and threads per block vary. Bit-exact checks pass for all 9 variants at all 4 shapes.
A pre-bound FFI callable and preallocated output are captured 64 times per CUDA graph.
20 replays per measurement, 7 shuffled repetitions. Values below are median microseconds per kernel.
These timings isolate device work; they exclude Python, allocation, row preparation and model work.

Host-path screen: full AdaLN at [1,4096,2048] with GEMMs and LayerNorm retained.
20 warmup calls, 200 measured calls per repetition, 7 shuffled repetitions.
CUDA event interval includes gaps due to host submission; this is not isolated kernel time.
The original forward is used for eager. All outputs and gates match bit-exactly.
The checked_cached_ffi prototype has one eligibility check and a pre-bound FFI callable,
but bypasses some production wrapper/custom-op dispatch; only the separate full-model run tests the final patch.

Conclusion: the best screened geometry saves about 0.32 us at the target shape.
The larger microbenchmark effect comes from host dispatch. No CUDA geometry change was adopted.
Full-model speed must be judged using dispatch-abccba results, not these operator measurements.
