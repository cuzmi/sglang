> Experimental draft — do not publish as a performance improvement. The measured candidate regresses; results below are retained for review.

## Motivation

Anima evaluates `LayerNorm(x) * (1 + scale) + shift` in every AdaLN. The default 28-block transformer has three gated AdaLN sites per block and one ungated output site (85 per transformer forward). SGLang already provides a fused CUDA modulation kernel that preserves the eager FP16/BF16 rounding boundaries.

## Modifications

- Reuse `modulate_scale_shift` after the existing LayerNorm for eager CUDA FP16/BF16 inputs.
- Convert the chunked `[B, 1, D]` scale/shift views to contiguous `[B, D]` rows. This only copies the small modulation tensors when needed; it does not copy the `[B, S, D]` activation.
- Preserve the original expression during `torch.compile` tracing and for non-CUDA/FP32 inputs. The existing wrapper handles unsupported layouts/dtypes and kernel errors.
- Leave normalization reduction, gate values, attention, weights, and scheduler unchanged.

## Accuracy Tests

- Standalone CUDA validation: **36/36** complete AdaLN comparisons are bit-exact against the original expression, including gated and ungated modules, batch 1/2, sequence lengths 17/1024/4096, hidden size 2048, and FP16/BF16/FP32. The 24 low-precision cases assert an actual fused CUDA call; the 12 FP32 cases assert eager fallback. Gate tensors also match exactly.
- Warmed CUDA graph capture/replay of the gated BF16 batch-2 AdaLN is bit-exact. This is an operator-level check, not a full-pipeline CUDA graph benchmark.
- Existing modulate tests: **12 passed**. Existing Anima CPU/CUDA suites: **17 passed**, including the checkpoint-free Cosmos transformer reference comparisons.
- All eight 1024x1024 unprofiled images and both separate diagnostic images have identical decoded RGB pixels and identical PNG bytes. Pixel SHA256: `2c12b2376dadcaac1f4b074f169b81ba15f9cf19b07832c21232fd220fe7a20c`.
- A second workload (512x512, seed 123, 30 steps, otherwise the same settings) also produces identical baseline/candidate pixels: `e214f0f579547bc3f045106f7bdf302b67f4a9c77436febffe5c929742f86702`.
- The real-model candidate diagnostic records 5,270 eligible fused calls, with no disabled fast path. First-observed checks pass for both modulation row strides at `[1,4096,2048]` BF16: gated `[6144,1]` and ungated `[4096,1]`.

## Speed Tests and Profiling

The initial call-site integration is a **negative performance result** on this workload. It is not ready to submit as a speed optimization.

| Arm | Worker request (ms) |
| --- | ---: |
| 01-baseline | 3792.13 |
| 02-candidate | 3980.27 |
| 03-candidate | 3987.43 |
| 04-baseline | 3830.50 |
| 05-baseline | 3730.83 |
| 06-candidate | 4031.34 |
| 07-candidate | 3988.64 |
| 08-baseline | 3883.55 |
| Baseline mean | 3809.25 |
| Candidate mean | 3996.92 |

The candidate adds 187.67 ms (**4.93% slower**). Baseline A/A range: 3730.83–3883.55 ms (spread 152.72 ms). Candidate B/B range: 3980.27–4031.34 ms (spread 51.07 ms). Each ABBA block regresses, and every candidate sample is slower than every baseline sample. Four samples per arm establish only this finite workload result, not a latency distribution.

Environment: NVIDIA H200; PyTorch 2.13.0+cu130; CUDA 13.0; Triton 3.7.1; Diffusers 0.37.0; Transformers 5.12.1.

Independent Torch Profiler captures confirm the intended CUDA replacement. In `ProfilerStep#4`, both variants execute 170 AdaLN calls (85 sites times two CFG forwards):

| Diagnostic count | Baseline | Candidate |
| --- | ---: | ---: |
| Modulation CUDA kernels | 510 | 170 |
| All CUDA kernels launched inside AdaLN | 1360 | 1020 |
| Sum of modulation kernel durations | 6.984 ms | 1.540 ms |

CUDA launch correlation identifies 170 add-one, 170 multiply, and 170 shift-add kernels in the baseline, replaced by 170 `modulate_scale_shift_kernel<__nv_bfloat16, 8>` launches. These profiled durations are attribution evidence only; they are excluded from the latency comparison.

The fused GPU work is cheaper, but the measured worker request is slower. This experiment does not establish the cause of that regression. Dispatch/launch overhead is a hypothesis to test, not a demonstrated explanation.

The standalone CUDA-event microbenchmark includes row conversion/copy costs. For BF16 `[1,4096,2048]`, the eager/fused means are 47.06/21.78 us; for `[2,1024,2048]`, they are 29.06/51.45 us. This further limits any shape-wide performance claim.
