> Local experimental draft. The final patch has a positive result on one H200 instance; repeatability across instances remains unverified. An earlier integration-only run regressed and is disclosed below.

## Motivation

Anima computes `LayerNorm(x) * (1 + scale) + shift` at 85 AdaLN sites per transformer forward. Reuse the existing bit-exact modulation kernel to replace the three eager modulation kernels with one, while keeping LayerNorm's reduction unchanged.

The modulation wrapper also checked eligibility twice and looked up the exported TVM FFI function on every invocation. This host work matters for Anima's frequent eager calls.

## Modifications

- Route Anima's eager CUDA FP16/BF16 modulation through `modulate_scale_shift`. Make only the small chunked scale/shift rows contiguous when necessary.
- Keep Anima's original expression for CPU, FP32 and `torch.compile` tracing.
- Cache the exported FFI callable and reuse the wrapper's completed eligibility check. Retain its error handling and eager fallback.
- Keep CUDA arithmetic, vector width and launch geometry unchanged.

## Accuracy Tests

- 36/36 full AdaLN cases are bit-exact, covering FP16/BF16/FP32, batch 1/2, sequence lengths 17/1024/4096, hidden size 2048, gated/ungated outputs. The 24 low-precision cases verify actual fused dispatch; the 12 FP32 cases verify fallback.
- Warmed BF16 batch-2 AdaLN CUDA graph replay is bit-exact.
- Existing modulate suite: 12 passed. Existing Anima CPU/CUDA suites: 17 passed.
- All six full-model requests below have identical decoded RGB pixels and PNG bytes. Pixel SHA256: `2c12b2376dadcaac1f4b074f169b81ba15f9cf19b07832c21232fd220fe7a20c`.
- Pre-commit checks pass for both changed files. No new repository unit tests are added; the additional validation lives in the standalone experiment harness.

## Speed Tests

One H200, BF16, TP1, FA attention, one 1024x1024 image, 30 steps, CFG 4, seed 42. Compile and CUDA graph disabled. Each fresh process performs one same-resolution one-step warmup request. The six unprofiled arms run in ABC-CBA order in one container on one GPU:

| Order | Variant | Worker request (ms) |
| --- | --- | ---: |
| 1 | eager | 3163.64 |
| 2 | initial_mount | 3084.66 |
| 3 | cached_dispatch | 3024.22 |
| 4 | cached_dispatch | 3031.38 |
| 5 | initial_mount | 3116.98 |
| 6 | eager | 3154.14 |

| Variant | Mean (ms) | Range (ms) |
| --- | ---: | ---: |
| eager | 3158.89 | 3154.14–3163.64 |
| initial_mount | 3100.82 | 3084.66–3116.98 |
| cached_dispatch | 3027.80 | 3024.22–3031.38 |

The final cached-dispatch patch reduces mean worker request latency by **4.15%** versus eager and **2.35%** versus integration alone in this run. Only two samples per variant were collected; this is a finite workload comparison, not a latency distribution or a cross-instance speed guarantee.

`total_duration_ms` excludes model loading, warmup and PNG saving. Unsynchronized denoise-stage timings are not presented as isolated GPU latency.

**Prior negative evidence:** the earlier integration-only ABBA experiment on a different Modal instance was 4.93% slower than eager (3809.25 vs 3996.92 ms, four samples each). Integration alone is 1.84% faster on the current instance. Do not pool the absolute times or describe the new patch as a proven explanation for the earlier regression. The current within-instance comparison directly supports reducing dispatch overhead; cross-instance robustness still needs confirmation.

Environment: NVIDIA H200, PyTorch 2.13.0+cu130, CUDA 13.0, Triton 3.7.1, Diffusers 0.37.0, Transformers 5.12.1, apache-tvm-ffi 0.1.11.
Model: `circlestone-labs/Anima-Base-v1.0-Diffusers` @ `073c3a9db359c31ad0e8aa268d15775473c2176c`.
Baseline: `6fa3fe69e2e5e19b75cadd9fc285b72634551992`.
Final source is that baseline plus the two-file patch; every arm records model/backend SHA256 values, and the CUDA source hash is asserted unchanged.

## Supporting Experiments

This is elementwise modulation, so there is no GEMM reduction dimension K. A separate nine-configuration launch-geometry screen varied rows per block and threads per block, retaining vector width 8. All variants were bit-exact at four BF16 shapes. At `[1,4096,2048]`, median CUDA-graph kernel time was 8.432 us for the default 4 rows/256 threads and 8.109 us for 1 row/128 threads. The 0.322 us reduction was too small to motivate changing the shared CUDA geometry in this patch.

A separate full-AdaLN host-path microbenchmark measured 94.554 us for the initial wrapper and 83.616 us for a single-check, cached-FFI prototype (eager: 86.614 us). These event intervals include host submission gaps; the prototype is not the exact production wrapper. The full-model comparison above measures the exact final patch.

Earlier separate profiler captures of the initial integration show 510 modulation kernels becoming 170 in a middle denoise step (170 AdaLN calls, including both CFG forwards). The final patch uses the same CUDA kernel. That trace establishes the replacement, not the final patch's latency benefit; profiled times are excluded from the speed table.
